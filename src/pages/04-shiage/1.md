## 情報を最新にする

移した担当セクションの中身は、今のサイトのままで古くなっています。最新にしましょう。

- 研究: 今動いているプロジェクトを、先輩や先生に聞いて確かめる
- 業績: 2024 年より後の発表を、研究室の Slack や先輩の業績一覧から集める
- リンク: すべて開いてみて、切れているものを直すか消す

分からないことは、推測で書かずに人に聞いてください。サイトに載る情報は研究室の公式な情報です。

## pull request: 取り込みを頼む

自分の branch の変更を `renewal` に取り込んでもらうには、pull request（プルリクエスト、略して PR）を出します。「この変更を取り込んでください」という依頼です。

1. 自分の branch を push します。

   ```sh
   git push
   ```

2. GitHub で [sfc-icar/sfc-icar.github.io](https://github.com/sfc-icar/sfc-icar.github.io) を開くと、「Compare & pull request」というボタンが出ています。押します。

3. 取り込み先（base）が `renewal` になっていることを確かめます。

4. 説明欄に、次の 2 つを書きます。

   - 何を変えたか
   - どうやって確かめたか（例: `npm run dev` で表示を確認した、リンクを全部開いた）

5. 「Create pull request」を押します。

先輩が変更を読んで、コメントをくれます。直すところがあれば、同じ branch で直して push すれば、PR に自動で反映されます。問題がなければ、先輩が取り込みます。

## 公開の仕組み

全員の担当がそろったら、`renewal` を main に取り込みます。すると、自動で公開されます。

<figure>
  <img src="../../images/deploy.svg" alt="push すると GitHub Actions がビルドし、GitHub Pages で公開される" />
  <figcaption>main に変更が入ると、GitHub Actions がビルドし、GitHub Pages が公開する</figcaption>
</figure>

- GitHub Actions: GitHub の上で、決まった作業を自動で実行する仕組み。ここでは Astro のビルドをする
- GitHub Pages: ビルドしてできた HTML を、Web サイトとして公開する仕組み

`npm run dev` のときに手元で Astro がやっていた組み立て（ビルド）を、GitHub が代わりにやってくれる、ということです。

## おわりに

ここまでで、あなたは次のことができるようになりました。

- git で変更を記録し、GitHub でみんなと共有する
- HTML と CSS を読んで、どこを直せば何が変わるか分かる
- 型と中身を見分けて、部品とデータに分ける
- 変更を PR で取り込んでもらい、公開する

来年の新人は、あなたが作った新しいサイトでこのチュートリアルを進めます。メンバー欄に 1 行足すだけで済むのは、あなたのおかげです。
